# Project Structure

For an easy code walkthrough, see `CODE_EXPLANATION.md`.

This project keeps the original mnistCUDNN files in place and adds a camera
driven YOLO-to-PGM wrapper pipeline around them. The final demo entry point is
`run_pgm_all.sh`.

## Runtime Flow

```text
./run_pgm_all.sh
  -> scripts/demo_preflight.sh
  -> scripts/run_pipeline.sh
  -> scripts/clean_outputs.sh
  -> scripts/run_yolo.sh
  -> yolo/detect_video.py
  -> camera source from yolo/config.yaml, or YOLO_SOURCE/CAMERA_INDEX/VIDEO_PATH
  -> pgm_output/*.pgm
  -> scripts/run_mnist_one.sh for each PGM
  -> summary
```

## Important Files

- `run_pgm_all.sh`: entry point for the demonstration; fill `answers=(...)` for evaluation.
- `ocr.py`: compatibility entry point for `--video`/camera inputs and single-PGM MNIST runs.
- `answers.txt`: optional whitespace-separated ground truth fallback for local sample runs.
- `yolo/config.yaml`: camera/video source, YOLO weight, PGM output, display, and duplicate filtering settings.
- `yolo/detect_video.py`: detects digits from camera/video and saves segment-level PGM files.
- `yolo/detect_images.py`: saves PGM files from still images or image folders.
- `yolo/dedupe.py`: saves only one PGM per visible digit segment.
- `yolo/save_pgm.py`: converts detected crops into 28x28 MNIST-style PGM files.
- `scripts/run_mnist_one.sh`: runs the existing MNIST code for one PGM image.
- `scripts/profile_mnist_pipeline.sh`: creates baseline/optimized timing reports.
- `data/*.bin`: mnistCUDNN runtime weights used by the C++ runner.
- `data/trained_bins_aug68.zip`: archived trained LeNet weight package and preview samples.
- `data_old/*.bin`: previous runtime weight backup.
- `yolo/weights/best.pt`: expected final detector location for the demo.

## Duplicate Save Rule

The tracker saves a digit when a stable new segment is detected. Repeated
detections across adjacent frames are ignored while the same digit remains
active. After enough missing frames, the segment closes and a later detection of
the same number can be saved again.

## Final Checkpoints

- YOLO training reads the base model configured as `yolo11n.pt`.
- After training, `yolo/train_yolo.py` copies the best detector to `yolo/weights/best.pt`.
- The live demo expects `yolo/weights/best.pt` unless `YOLO_WEIGHTS` is set.
- Before submission, confirm that the final trained detector is present at that path or document the explicit `YOLO_WEIGHTS` override.

## Submission Rule

Submit code, scripts, configuration, trained weights, and the report. Do not
submit generated `pgm_output/*.pgm` files as required outputs. Keep
`pgm_output/debug/*.png` only when they are intentionally used as report
evidence. Report accuracy and runtime using the sample video run.
